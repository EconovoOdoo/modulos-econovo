Each attendance record is processed inside an isolated database savepoint. If one record fails (overlap, invalid timestamp, missing employee), only that record is rolled back — the rest continue processing normally.

Overlapping Attendance

Employee already has an active shift covering the punch timestamp. Odoo rejects duplicate overlap.

Invalid Timestamp

Device sent a corrupted or impossible date (e.g. Jan 1, 1970 after a power reset).

Deleted Employee

Employee was removed from Odoo but still punches on the biometric device.

Unmapped Device User

Device user ID not linked to any Odoo employee. Logged as a warning for admin review.

Quick Setup Guide

Get your ZKTeco devices connected in minutes. Choose the method that matches your network.

Direct Mode (PyZK) Setup

For local network / VPN deployments
Requirement: Odoo server must be able to reach the device IP on port 4370 (UDP).
  1. Install the PyZK2 library on your Odoo server (maintained fork, Python 3.12 compatible): 
    pip3 install pyzk2
  2. Find the device IP: On the device menu, go to COMM → Ethernet → IP Address.
  3. In Odoo, go to Attendances → ZK Devices → Create.
  4. Fill in:
    • Name: e.g. "Main Entrance"
    • IP Address: The device IP (e.g. 192.168.1.201)
    • Port: 4370 (default)
    • Connection Mode: Direct (PyZK)
    • Attendance Mode: Choose your preferred mode
  5. Click "Test Connection". If successful , you're ready!
  6. Map employees: Set each employee's ZK Device User ID in their HR profile (must match the ID on the device).
  7. Click "Download Attendance" to fetch records, or enable the Scheduled Action for automatic downloads.

Cloud Mode (ADMS) Setup

For Odoo.sh, cloud hosting, or remote sites
No port forwarding needed! The device initiates the connection to your Odoo URL.
  1. Ensure your Odoo is accessible via a public URL or IP (e.g. mycompany.odoo.com or 192.168.1.10:8069).
  2. In Odoo, go to Attendances → ZK Devices, open (or create) the device record and copy the Device Server Address from the ADMS Cloud Settings group.
  3. On the ZKTeco device, go to COMM → Cloud Server Setting:
    • Enable: Yes
    • Server Address: paste the Server Address (firmware) value from the device record in Odoo
      ⚠ Do NOT type https:// — firmware takes host + path only, no protocol prefix.
    • Server Port: paste the Server Port (firmware) value from the device record in Odoo
      8069 = direct Odoo (no proxy)  ·  80 = HTTP via nginx  ·  443 = HTTPS via nginx
    • HTTPS / SSL toggle (if present): turn ON when port is 443, OFF for port 80 or 8069
  4. Restart the device. It connects automatically and registers itself in Odoo.
  5. Configure the auto-created device record: set Connection Mode, Attendance Mode, and map employees by Device User ID.
  6. Done! Attendance is pushed automatically in real-time.
Single Database — The Device Server Address looks like myodoo.com/db/my_database. Configure it exactly as shown — do not add https://.
Multiple Databases on the Same Server — Each database has its own unique Device Server Address containing /db/database_name. Configure each physical device with the address of the database it belongs to. Always copy from the Odoo device record — do not type manually.
Hybrid Mode — Best of Both Worlds

Want automatic attendance push (ADMS) plus hardware control like LCD messages, voice feedback, and door unlock (PyZK)? Set Connection Mode = Hybrid. The device pushes data via ADMS, while Odoo uses PyZK for hardware features.

Attendance (ADMS side)
  • Configure the Device Server Address exactly as in the ADMS setup above (with /db/database_name)
  • Multi-database routing works the same way as ADMS mode
  • Real-time push — no manual download needed
Hardware Control (PyZK side)
  • Requires Odoo to reach the device on TCP port 4370
  • On-premise Odoo: works on same LAN
  • Cloud Odoo: requires VPN or port forwarding on the site router
  • If network access is not possible, use ADMS-only mode (attendance still works, hardware control features are not available)

SIGNATURE FEATURE — ADMS Custom Hour Offset EXCLUSIVE

The ONLY Odoo ZKTeco module on the app store that solves the firmware-level timezone bug with a one-click software fix — no server access, no nginx, no device changes required.

The Problem: ZKTeco firmware silently shifts device clock by ±1 to ±12 hours after HTTP handshakes — a well-known bug every other ADMS module suffers from silently.

Our Solution: Set a single offset value (e.g. -3) on the device record. Every incoming punch is auto-corrected in software — the physical device stays untouched. Done in 5 seconds.

Why this matters: Most Odoo ZKTeco modules do not even acknowledge this firmware bug. We document it, warn you, and give you a working bypass — because you deserve a real fix, not days of frustration.

Troubleshooting & Common Issues
"ATTLOG: 1 failed" / Employee Not Found

Device sent a punch for a user ID not linked to any Odoo employee.

Fix: HR → Employees → open/create the record → set Device ID Number to match the ID on the device.

ADMS Device Not Appearing in Odoo

Device connects but doesn't show in the device list.

Fix: Create the device in Odoo first with Connection Mode = Cloud (ADMS) and matching Serial Number; then restart the device.

ADMS Data Goes to Wrong Database (Multi-DB)

On a server with multiple databases, punches land in the wrong database or go missing.

Fix: Open the device in Odoo → copy Device Server Address from ADMS Cloud Settings → paste it as the Server Address in device firmware (COMM → Cloud Server Setting). The address includes /db/database_name which routes the device to the correct database.

ADMS Device Connected by IP/Domain — No Serial Number

Device uses IP or domain address in ADMS firmware settings but has no serial number (shows as 0). In multi-database setups the IP/domain fallback won't reach the right database without the correct URL.

Fix: Manually create the device record in Odoo first with the device IP. Then copy Device Server Address and set it as the Server Address in the device firmware — this includes the /db/database_name path that routes the device to the correct database even when matching by IP.

How to Find Device User ID

Each enrolled user has a unique ID number.

On device: Menu → User Mgt → All Users → select user. In Odoo log the error shows the exact ID (e.g. '6666').

ADMS Auto Time Sync

In ADMS mode, device clock is synced from the server on every heartbeat.

Device time = Server Time. Manual time changes on the device will revert. To change device time, change server time.

⚠ Known ZKTeco Firmware Timezone Issue
Many ZKTeco devices silently use the HTTP Date response header to adjust their internal clock when communicating via the ADMS push protocol. This is a well-known firmware behaviour across multiple ZKTeco models and firmware versions. The result: attendance timestamps can shift by 1–12 hours even though the device screen still shows the correct local time. Most other Odoo ZKTeco modules do not warn you about this.

Option A — Nginx Fix (Recommended for sysadmins)
If your Odoo server runs behind an nginx reverse proxy, suppress the Date header on /iclock/ routes. Add this location block before your main location / block:

location /iclock/ { proxy_pass http://<odoo-upstream>; proxy_http_version 1.1; proxy_set_header Host $host; proxy_set_header X-Real-IP $remote_addr; proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for; proxy_set_header X-Forwarded-Proto $scheme; proxy_redirect off; proxy_hide_header Date; more_clear_headers Date; }

Requires the libnginx-mod-http-headers-more-filter package (sudo apt install libnginx-mod-http-headers-more-filter).

Option B — Custom Hour Offset (No server access needed)
If you cannot modify nginx, or if the time shift persists after fixing nginx, use the built-in ADMS Time Offset field on the device record. Set it to the inverse of the observed drift (e.g. if attendance is +3 hours ahead, set offset to -3). The correction is applied automatically to every incoming ADMS punch — no device or server changes required.
