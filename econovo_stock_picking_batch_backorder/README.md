# Stock Picking Batch Backorder

Groups the backorders generated by the validation of a batch transfer into a
new batch transfer, instead of leaving them as standalone transfers.

## Problem

When a batch transfer is validated with partial quantities, Odoo creates one
backorder per transfer (`stock.picking._create_backorder`) and none of them is
linked to a batch, because `batch_id` is declared with `copy=False`. The
operator has to rebuild the working set by hand.

## Solution

A checkbox is added to the native "Create Backorder?" wizard
(`stock.backorder.confirmation`):

> **Create a new batch with the backorders**

It is only displayed when at least one of the transfers being validated belongs
to a batch, and its default value comes from the operation type.

When ticked, `stock.picking._create_backorder` is extended to group the
generated backorders by their origin batch and to create one new batch per
origin.

## Configuration

Inventory > Configuration > Operation Types:

| Field | Description |
|---|---|
| **Batch Backorders** | Default value proposed on the wizard (enabled by default) |
| **Backorder Batch Status** | Status of the new batch: *Draft* (default) or *In Progress* |

## Behavior

* One new batch per origin batch when several batches are validated at once.
* The new batch inherits `company_id`, `user_id` and `is_wave` from the origin.
* A batch is created even when there is a single backorder.
* Backorders in a state not accepted by `stock.picking.batch._sanity_check` are
  skipped, so the validation can never be aborted by this feature.
* Transfers that do not belong to a batch are ignored.

## Interaction with Automatic Batches

The batch is assigned while the backorders are created, that is *before*
`stock_picking_batch`'s `button_validate` calls `_find_auto_batch()` on them.
Since `_find_auto_batch()` returns early for transfers that already have a
batch, this module takes precedence without patching the automatic batches
feature.

## Traceability

* `origin_batch_id` on the new batch, displayed on the form view.
* *Backorder Batches* smart button on the origin batch.
* A message is posted in the chatter of the origin batch with a link to the new
  one.

## Barcode app

The option is not available in the Barcode app with this module alone: the
barcode client skips the backend wizard. Install
`econovo_stock_picking_batch_backorder_barcode` to get the checkbox in the
barcode *Incomplete Transfer* dialog.

## Requirements

* `stock_picking_batch` (core)
